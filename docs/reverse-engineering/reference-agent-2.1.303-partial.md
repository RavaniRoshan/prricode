### Runtime provider routing (this phase)

This is the decisive provider finding. The module that owns the catalog also owns the **route selector** `xe()`:

```
if (Br() || aet() || cet()) return "gateway";
CLAUDE_CODE_USE_BEDROCK              -> "bedrock"
CLAUDE_CODE_USE_FOUNDRY              -> "foundry"
CLAUDE_CODE_USE_ANTHROPIC_AWS        -> "anthropicAws"
CLAUDE_CODE_USE_ANTHROPIC_GOOGLE_CLOUD -> "anthropicGoogleCloud"
CLAUDE_CODE_USE_MANTLE               -> "mantle"
CLAUDE_CODE_USE_VERTEX               -> "vertex"
otherwise                            -> "firstParty"
```

`wd(model)` layers a per-model override: with Bedrock+Mantle enabled, an `anthropic.*` model resolves to `mantle`; otherwise, if the catalog has `provider_ids[route] === null` while `provider_ids[mantle] !== null`, the model resolves to `mantle`.

The **runtime client factory** `GU` in `chunk-e0p2z0nm.js` (role `callable:callable:function:263357:272594`, fingerprint `9bc0ee02c5e0c3b96baa38eab3f6a6b4927f9650cdd87f2a0b56e2e6f94eb431`) turns the resolved route into a concrete client. Observed dispatch order: `gateway` → plain client with `baseURL: <pinned url>` and `Authorization: Bearer <jwt>`; `bedrock` → `AnthropicBedrock` (`chunk-1njnz05e.js`); `foundry` → `AnthropicFoundry` (`chunk-m5c0c57d.js`) with an Azure AD `DefaultAzureCredential` bearer provider; `anthropicAws` → `AnthropicAws` (`chunk-a3dhk724.js`); `anthropicGoogleCloud` → `AnthropicGoogleCloud` (`chunk-7qjrjq0k.js`); `mantle` → `AnthropicBedrockMantle` (`chunk-1njnz05e.js`); `vertex` → `AnthropicVertex` (`chunk-jdnh8sjs.js`) with `buildVertexGoogleAuth` (`chunk-hcq5r9nd.js`); otherwise the first-party client with an API key or OAuth token. - Ghidra heap is capped at 1,536 MiB. Expensive broad analyzers are disabled for targeted function inspection; the ASCII string analyzer is enabled for the string search.

## Current conclusions and limits

- The pinned distribution routes its CLI through a 285.8 MB x86-64 Bun ELF; the npm JavaScript package is an install/launcher wrapper.
- Native pseudocode establishes startup and helper dispatch. Targeted native evidence maps the `apply-seccomp` worker's namespace/mount/fork/filter setup and its seccomp user-notification supervisor. Direct call imports are resolved, but the full syscall handler policy and the application's runtime selection conditions remain incomplete. Native strings expose product vocabulary.
- The JavaScript semantic graphs are now available **untruncated per module** for the modules that matter most, which is what made the provider request pipeline, the runtime provider client factory, the model catalog, the settings precedence model, the hook event matrix, and the MCP control surface legible as relationships. Coverage is still **partial** in the sense that: (a) REA retains at most 20,000 unknowns per file and 100,000 overall, with omitted emission counts reported per family and reason; (b) member calls (`this.method(...)`) do not produce `calls` relations, so their targets remain unknown; (c) the transfer byte budget caps the largest modules, which were retried at a lower per-file ceiling; (d) a whole-image Ghidra inventory remains unavailable.
- The provider story is now **resolved statically at the client-construction level**: the route selector yields exactly one active route, the runtime client factory dispatches to one of eight provider-specific SDK subclasses, and the model catalog is a built-in, provider-owned table with per-provider model IDs. The absence of a user-managed multi-provider connection registry is a **negative observation with a scope limit**, not a proof of absence across the whole artifact.
- **The local gateway is a second, separately implemented request path** in the artifact. Its relationship to the `gateway` catalog route (a pinned remote URL plus a JWT) is not established.
- The permission model, the settings tier model, the hook event matrix, the MCP control surface, the MCP transport semantics, and the session storage layout are **observed**. The agent loop's tool-call scheduling, the session resume algorithm, and the ordinary per-key settings merge remain **partial**.
- Ghidra's inability to resolve 495 external symbols, partial call relationships, and a reduced analyzer profile must be reported with any downstream conclusions.
- REA's Ghidra project is ephemeral; interrupted/cancelled operations discard analysis state. Completed canonical Evidence records, not Ghidra project files, are the current durable artifacts.
