### Decisions captured

- Full observable feature parity for the pinned target is the project objective; implementation is dependency-ordered but not downscoped to an MVP.
- Multiple simultaneously configured providers and a model catalog/manager are required product extensions, informed by Kimi Code. The REA evidence now shows precisely what the reference agent has: a **built-in, provider-owned** model catalog with per-provider model IDs across eight providers, a route selector that yields **exactly one active route**, and a per-provider base-URL/host policy. It has **no** user-managed multi-provider connection registry. This implementation's manager is therefore an extension, and the catalog's shape is the reference for this implementation's provider-owned catalogs.
- Use stable task IDs and this file plus plan checkboxes as durable progress markers. A handoff must update this file and include an exact next action.
- Provider credentials are represented by explicit environment/OS credential-store references. A model catalog is not allowed to select or read secrets.
- Native and source findings remain bounded to the cited Evidence records. Model/provider routing, MCP controls, permissions, and agent/session paths have been tied to named modules and functions; their end-to-end transitions are still under investigation. Do not infer behavior from string presence alone.
- **New:** the REA evidence for the provider adapters was re-derived from the target's **own bundled modules** rather than the public SDKs, which corrected two external-research findings: the target **throws** on a Foundry `baseURL`/`resource` conflict rather than picking a winner, and the `?beta=true` marker is a distinct path variant that the Bedrock and Vertex adapters strip. When the public SDKs and the pinned binary disagree, the binary wins.
- **New:** the seccomp user-notification supervisor in the target **never denies** — its response struct's `error` field is never written, so every intercepted filesystem syscall is permitted and only observed. The `apply-seccomp` helper is an audit mechanism, not the sandbox boundary. The 27-record dispatch table's metadata is decoded as argument indices.
- **New:** the target's SDK SSE parser accepts an **extended event vocabulary** (`agent.*`, `session.*`, `span.*`, `user.*`) that the public API does not document. The application consumes only `agent.message` and `user.interrupt` from it, so it is a forward-compatible parser rather than a multi-agent protocol.
- **New:** REA's per-file semantic-node ceiling is a hard analytical constraint. All future JavaScript semantic work must use the per-module procedure in `/home/shiva/opt/reference-agent-rea/analysis/`. Repeating a multi-module `analyze_javascript_application` call is a known-wasteful operation and is prohibited by the handoff runbook.
