# AGENTS.md — how to work on PRRICODE

Guide for coding agents (and humans acting like disciplined implementers) working in this repository. The long form of everything here is [`docs/reverse-engineering/HANDOFF.md`](docs/reverse-engineering/HANDOFF.md); this file is the short, binding contract.

## What this repository is

A coding agent for the terminal, built in two layers: **layer 1** is a parity clone of a pinned reference build with a machine-checkable bar; **layer 2** is the product's own identity — protocol, model layer, pipeline, approvals, motion, goldens, product, verification suite.

## Hard rules

1. **Naming rule.** No third-party product or company name anywhere — source, comments, docs, commit messages, identifiers. Target *data* keeps its names (model ids, hostnames, env vars, config keys). `tests/contracts/naming.test.ts` enforces it.
2. **Honest reporting.** A difference from an observed target behaviour is a `mismatch` — never `partial`. `match` requires nothing uncompared. Project extensions with no target counterpart stay `not-tested`, never `match`.
3. **Never fake success.** An operation that needs an absent capability refuses with the capability named (the `capabilityUnavailable` shape). This is a *tested* property, not a promise.
4. **Never execute the target** beyond the single bounded `--version` check.
5. **Path-limited commits.** `git commit <paths> -m "..."` with your own paths only. Never `git add -A`, never a broad `git add`, never a bare `git commit`. Sessions share the working tree.
6. **RAM discipline.** ~7.5 GiB guest that restarts unprompted: commit early; measure heavy runs (`/usr/bin/time -f "PEAK %M KB in %e s"`); never hold the extracted tree in-process; tree-wide reads go through `grep`; never load `analysis/modules/` (2.8 GB) or `*.json.gz` graph files; at most 2 concurrent subagents.
7. **Test flags.** `npx vitest run --maxWorkers=4` — two `mcp-manager` timing tests flake at the default worker count.
8. **Orchestrator-owned files.** `scripts/verify-rea.ts`, `scripts/rea-scan.ts`, `tests/compatibility/`, `docs/compatibility/results.md` and `docs/compatibility/feature-matrix.md` are re-measured by the orchestrator; an implementer does not edit them.
9. **Milestone etiquette.** Read the milestone in the plan first; test-first; no `any`; guard caller-supplied object lookups with `Object.hasOwn`; never weaken an existing assertion; the full suite must be green before a push.
10. **Specifications come before code.** Layer-2 surfaces were specified in `docs/protocol/*.md` and implemented to contract; new surfaces follow the same pattern.

## The verification commands

```bash
bun run scripts/regenerate-report.ts   # the clone's parity report
bun run scripts/verify-rea.ts          # re-derives 13 surfaces; must pass
bun run scripts/verify-product.ts      # the product suite — 4 kinds
npx vitest run --maxWorkers=4          # everything
npx tsc --noEmit                       # the types
```

Golden frames (`tests/visual/`) are regenerated deliberately with `bun run tests/visual/regenerate.ts` — never as a side effect of a test.
